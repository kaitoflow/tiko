# v0.2.0 使用与边界

协调者交接目的、权限、原话和材料，专家判断实际工作方法。重要偏离单独说明，mode 行仍只填枚举；目的与授权范围不变。

## CLI 与 MCP

```sh
node bridge/tiko.mjs prepare --task-file examples/task.json --task-id TASK_001 --project /absolute/project/root --project-name '项目名'
```

prepare 输出 JSON 的 message 字段；它不发送、不登记绑定、不读取账户状态。MCP 调用 gbot_send 时使用该字段、项目绑定的 target、同一 requestId、replyMode=manual，然后用 gbot_thread 主动读回。CLI send 接受同样 JSON 任务文件，也兼容文本文件；二者使用同一封套模块。

JSON 结构只校验输入类型、目标、范围和规则存在，不判断材料真实性、是否充分或模型输出质量。文本兼容模式不强制来源分层，专家必须说明来源限制。MCP 直接发送任意文本不会自动套用 v0.2.0 协议，不能假称代理已强制执行。

CLI 正常项目路径在发单前登记任务ID，未知结果也阻止再次登记；MCP 和 legacy 没有本地登记保护，上游服务端幂等未经验证。未知结果只读回，不换入口重发。

## 回读

保持 completed_reply_observed 含义兼容：仅表示观察到格式完整的回复（包括 needs_user/needs_evidence）。protocol_valid 同义；round_goal_reported_complete 仅表示专家声称完成本轮，quality_verified=false 表示程序不评价质量。人工检查内容后再判断任务是否达成。

格式检查新增拒绝冲突枚举头字段、重复边界及显式用户回显；旧的规范 v0.1 回复保持兼容。协议检查和 JSON 转义都不是安全沙箱，提示注入仍需宿主授权边界和结果核验。

## 建议反馈
